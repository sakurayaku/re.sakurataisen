# Ludared Lua codec API

Technical reference for Lua codec authors. For workflow, reconstruction rules, confidence semantics, and project-file read policy, see [../SKILL.md](../SKILL.md).

> This reference follows the Lua API discussed and documented for Ludared. Check current Rust bindings for exact signatures, runtime error wording, and discovery behavior before relying on implementation-specific details.

## Runtime and environment

Ludared embeds **Lua 5.5 via mlua**. Lua strings support binary bytes, including NUL. Lua 5.3+ facilities include `string.pack`, `string.unpack`, `string.packsize`, integer arithmetic, and bitwise operators (`&`, `|`, `~`, `<<`, `>>`). Do not assume optional third-party modules are installed.

The global `LUDARED` exposes project paths:

```lua
local workspace = LUDARED.WORKSPACE
local project_root = LUDARED.PROJECT_ROOT
local scripts = LUDARED.SCRIPTS
```

These are filesystem paths, **not** virtual-artifact read APIs. Lua scripts are **not sandboxed**. They can access files, environment variables, and other standard Lua facilities; run only trusted scripts. Treat project and workspace files as read-only during Ludared operations.

Lua VMs are initialized separately for codec operations; do not rely on globals persisting across detection, decode, or encode. Codec modules are evaluated during discovery; keep initialization free of side effects.

## Writing a Lua codec

A Lua codec script returns a table with metadata and callbacks:

```lua
return {
  name = "Example codec",
  description = "Describe the format",
  version = 1,
  kind = "rebuild", -- "rebuild" or "patch"

  can_handle = function(data)
    return "likely" -- "no", "possible", "likely", "certain"
  end,

  decode_name = function(args)
    return "decoded"
  end,

  decode = function(data, args)
    return {
      { name = "part.bin", data = data },
    }
  end,

  encode = function(original, artifacts, args)
    return artifacts[1].data
  end,
}
```

This illustrates the API shape, **not** production-ready format recognition. The skeleton generated by `ludared codecs create` is another starting point; inspect the generated file and actual codec requirements.

### Metadata

| Field | Meaning |
| --- | --- |
| `name` | Human-readable display name (not the codec ID). |
| `description` | Human-readable description. |
| `version` | Codec version number. |
| `kind` | Lowercase `"patch"` or `"rebuild"`. |

### Callbacks

| Callback | Inputs | Return |
| --- | --- | --- |
| `can_handle(data)` | Binary input string | `"no"`, `"possible"`, `"likely"`, `"certain"` |
| `decode_name(args)` | Codec-specific argument string or `nil` | Suggested decode operation name |
| `decode(data, args)` | Binary input, arguments | Ordered array of `{name = string, data = binary_string}` |
| `encode(original, artifacts, args)` | Original parent bytes, ordered artifacts, arguments | Reconstructed binary string |

The `artifacts` argument to `encode` is **an array of records**, not a map keyed by artifact names:

```lua
local artifacts = {
  { name = "head.bin", data = head },
  { name = "tail.bin", data = tail },
}

local first = artifacts[1].data
```

Output names are relative virtual paths; artifact order is retained for encoding. Validate counts, names, lengths, and format constraints during reconstruction because overrides can modify artifacts. `decode_name` names a decode operation, not an individual artifact.

`args` is opaque to Ludared; each codec defines its own syntax. Do not assume JSON or `key=value` parsing.

### Encoding strategies

- `"rebuild"`: reconstruct the complete parent from artifacts; `original` is an empty string.
- `"patch"`: receive the current parent bytes and return the patched result, preserving unaffected regions.

Do not mix patch and rebuild on the same node. Successive patches on one node follow their declared order; independent branches do not have a guaranteed order. For supported inputs, unchanged artifacts should round-trip to the original bytes.

## Utility functions and builtin codecs

```lua
local hash = LUDARED.sha256(data) -- lowercase SHA-256 hex string
local prs = LUDARED.codec("std/sega/compression/prs")
```

`LUDARED.codec(id)` returns a handle to a **builtin Rust codec**, or raises a Lua error for an unknown ID. This is a factory/lookup function; the returned handle is an object.

### Read-only handle properties

| Property | Meaning |
| --- | --- |
| `prs.id` | Builtin codec identifier. |
| `prs.name` | Human-readable name. |
| `prs.description` | Human-readable description. |
| `prs.kind` | Lowercase `"patch"` or `"rebuild"`. |

### Handle methods

```lua
local confidence = prs:can_handle(data)
local artifacts = prs:decode(data, args)
local encoded = prs:encode(prs.kind == "patch" and data or "", artifacts, args)
```

- `can_handle(data)` returns lowercase `"no"`, `"possible"`, `"likely"`, or `"certain"`.
- `decode(data[, args])` returns the **same ordered array of `{name, data}` records** as a Lua-authored codec's `decode`.
- `encode(original, artifacts[, args])` accepts that same ordered array and returns binary data.
- Optional `args` are codec-specific. Use consistent arguments for decode and encode when required by the codec.

**There is one artifact representation across Lua-authored and builtin codecs.** Both APIs use lowercase kind and confidence strings; the Rust `Display` representation does not define the Lua spelling.

## Project paths and module loading

```lua
local helper = dofile(LUDARED.SCRIPTS .. "/shared/helper.lua")
local file = assert(io.open(LUDARED.WORKSPACE .. "/tables/glyphs.tbl", "rb"))
local contents = file:read("*a")
file:close()
```

`require` does not automatically include the scripts root in `package.path`; configure lookup explicitly if needed. Reading project-specific lookup tables, read-only databases, and pristine reference data can be appropriate, but dependencies may be untracked. Document them and avoid volatile inputs. **Do not write to the workspace during Ludared operations.**

## Discovery and IDs

Codec IDs are `scripts/` plus the path relative to the configured scripts root, including `.lua` (for example `scripts/my_codec.lua` in CLI usage). Discovery loads codec modules eagerly.

The shared `ScriptDiscovery` scans `.lua` files recursively, skips `shared/` subtrees at any depth, and classifies files under `tests/` directories as tests, including nested descendants. Other Lua files are codecs; `libraries/` has no special exclusion. Keep Lua fixtures and helpers under `shared/`, including inside test directories, to prevent automatic loading or execution.

## Test runtime

`ludared scripts test [PATH*]` executes discovered test scripts in a project. Selection and command examples are in [the Lua skill](../SKILL.md#lua-test-scripts).

Each test file executes at top level in a fresh Lua VM with `LUDARED.PROJECT_ROOT`, `LUDARED.WORKSPACE`, `LUDARED.SCRIPTS`, `LUDARED.sha256`, and `LUDARED.codec`. A successful script completes without error; a failed assertion or other Lua error stops the command. There is no automatic test-function discovery or required return value.

Load a Lua codec module explicitly and call its callbacks with dot syntax, as ordinary functions:

```lua
local codec = dofile(LUDARED.SCRIPTS .. "/my_codec.lua")
local fixture = dofile(LUDARED.SCRIPTS .. "/tests/shared/fixture.lua")
local artifacts = codec.decode(fixture.data, fixture.args)
local original = codec.kind == "patch" and fixture.data or ""
assert(codec.encode(original, artifacts, fixture.args) == fixture.data)
```

This example assumes a fixture module returning `{ data = ..., args = ... }` for a supported round-trip input. Use `LUDARED.codec(id)` and colon syntax for builtin Rust codecs; it does not look up Lua codecs. `require` needs the same explicit search-path setup as in codec scripts. Use `assert()` and `print()` directly unless the project has configured a test framework.

## Binary parsing example

```lua
local value, next_offset = string.unpack("<I4", data, 1)
local first_byte = string.byte(data, next_offset)
local flags = value & 0xFF
local packed = string.pack("<I4", value)
```

Lua string indices are 1-based. `string.unpack` returns the next position; validate input bounds and integer ranges.

## Errors

Use descriptive Lua errors for malformed inputs, invalid arguments, and inconsistent reconstruction artifacts. Eager module loading means a malformed codec can prevent project initialization. Consult current Rust bindings for exact error messages.
